# Local Workout Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подключить четыре арта, комиксные реплики, оценки упражнений и осторожные локальные рекомендации после тренировки.

**Architecture:** Чистый модуль coach.ts вычисляет советы и выбирает контекст; каталог coachCopy.ts хранит реплики. React-компоненты отвечают за анкету, презентацию и настройки, существующее хранилище сохраняет необязательные поля без изменения версии базы.

**Tech Stack:** React, TypeScript, Vite, IndexedDB, Vitest; без новых runtime-зависимостей.

**Spec:** docs/superpowers/specs/2026-10-06-local-coach-design.md

## Global Constraints

- Не подключать сервер, платный ИИ, Финансовый Оракул или внешнюю базу.
- Не менять программу автоматически. Фоновые push и гонг — отдельная задача.
- Старые записи без полей остаются читаемыми и не получают придуманных оценок.
- Ничего не считать выбранным по умолчанию в анкете самочувствия и контекста.
- Не предлагать прибавку более 10% текущего веса; при слишком крупном шаге оставить прогрессию повторов.
- Не менее 6 реплик на каждый контекст; не повторять последние три при наличии альтернатив.
- Арты уже созданы; не генерировать заново. У пользовательской картинки приоритет.

## Review Focus

- Изменённая или сокращённая программа не должна ошибочно считаться полностью выполненной — задача 2.
- Болезнь или неизвестные оценки между обычными тренировками не должны исчезать при фильтрации и позволять прогрессию — задача 2.
- Сохранённая из тренировки программа не должна переносить старые оценки в новые занятия — задача 1.
- Ошибка IndexedDB не должна приводить к потере результатов или ложному сообщению об успешной оценке — задачи 1 и 3.
- Повторное открытие истории, изменение оценки и награды не должны создавать зацикленные модальные окна — задача 3.

## Задача 1: данные и совместимость

**Files:** types.ts, storage.ts, domain.ts, App.tsx; новые coachData.ts и coachData.test.ts.

**Interfaces:** Workout.coachFeedback?: {context?: 'normal'|'light'|'returning'|'time'; wellbeing?: 'good'|'fatigued'|'symptoms'; reviewedAt?: string; phraseId?: string}; WorkoutExercise.effort?: 'easy'|'normal'|'limit'; WorkoutExercise.equipmentSnapshot?: string; ExerciseDefinition.loadStep?: {value:number;unit:WeightUnit}; Settings.coachTone?: 'playful'|'neutral'; Settings.trainingDays?: number[] (0–6, местные дни недели). normalizeCoachData(state:AppState):AppState возвращает копию с допустимыми полями, не изменяя исходник.

- [ ] Написать тесты старого backup без новых полей, неизвестных enum, NaN/отрицательного шага, дней вне 0–6 и дубликатов; ожидать сохранения старых данных и удаления только неверных новых полей.
- [ ] Запустить pnpm test и увидеть падение новых проверок.
- [ ] Реализовать нормализацию на загрузке и импорте. Снимать equipmentSnapshot при создании упражнения тренировки. При сохранении программы и старте новой тренировки явно исключать effort/coachFeedback.
- [ ] Добавить тест: saveWorkoutAsProgram → startWorkout не наследует оценки; тесты круглого прохода backupJson/parseBackup сохраняют корректные поля.
- [ ] Перед первой записью оценки создать один снимок на устройство с отдельным маркером успешного создания; при ошибке снимка не сохранять оценку и показать повтор действия. Проверить отказ snapshot/save с восстановлением текущих данных.
- [ ] Полный pnpm test, затем отдельный commit данных.

## Задача 2: рекомендации и реплики

**Files:** новые src/coach.ts, src/coachCopy.ts, src/coach.test.ts.

**Interfaces:** CoachAdvice {exerciseId:string;kind:'hold'|'add-rep'|'add-weight'|'reduce'|'check-in';reason:string;targetWeightKg?:number;targetReps?:number;sourceUrls:string[]}; getCoachAdvice(state:AppState,workoutId:string):CoachAdvice[]; isFullProgram(workout:Workout):boolean; selectCoachPhrase(state:AppState,workoutId:string):{id:string;text:string;art:'proud'|'record'|'support'|'treat'}; nextTrainingDate(days:number[],now:Date):Date|null.

- [ ] Создать реальные fixtures двух сравнимых обычных занятий с хорошим самочувствием и easy: при плане 3×10/40 кг получить add-rep с целью 11 в одном подходе; без второй оценки получить hold/check-in. Запустить до реализации — FAIL.
- [ ] Реализовать сопоставимость ID, типа нагрузки, оборудования-снимка, числа подходов, плановых повторов и весов. Не соединять через неизвестные, облегчённые или послеболезненные занятия; не считать дубли внутри одного занятия разными тренировками. Только прошлые записи до анализируемой тренировки.
- [ ] Проверить стадии: две базовые easy → две следующие easy с превышением исходной цели → add-weight. При шаге 2 кг и весе 40 получить 42; при шаге 5 получить add-rep, поскольку >10%; без шага — запросить шаг без числовой прибавки. Сопоставимость плана проверять относительно сохранённого snapshot, не текущей редактируемой программы.
- [ ] Тесты: боль, returning, усталость, нет контекста, переменные веса, неизвестное оборудование, архив, будущая дата, нулевые веса, bodyweight/assisted блокируют числовую прибавку; кг/lb эквивалентны; одна трудность не reduce; две limit с недобором normal/good допускают один шаг снижения, не отрицательный.
- [ ] Реализовать только информационные советы с причиной, датами и ссылками из спецификации. Число подходов не увеличивать.
- [ ] Тесты full-program: исходный snapshot полностью выполнен → true; удалённое упражнение, пропуск, дополнительные компенсирующие подходы, свободная тренировка → false.
- [ ] Написать по 6 реплик на 7 основных контекстов в каждом тоне; дополнительно нейтральные контексты нулевых подходов и симптомов. Тестами проверить приоритет защиты, отсутствие последних трёх повторов и устойчивый phraseId при повторном открытии. Пересчитать контекст при исправлении данных; не хвалить за всю программу после удаления подхода.
- [ ] nextTrainingDate: без дней null; выбранный сегодня допустим как план, после выполненного сегодня занятия UI ищет следующий выбранный день; проверить переход воскресенье→понедельник и месяц, не использовать UTC-срезы для локальной даты.
- [ ] Полный pnpm test и commit вычислительного модуля.

## Задача 3: завершение, персонаж и рекомендации

**Interfaces:** WorkoutCoach({data,workoutId,update,onShowRewards,saveStatus}); update сохраняет существующим путём AppState, не создаёт отдельную базу. Пользоваться интерфейсами задач 1–2. Проверки компонента через React DOM в доступной среде тестирования; если потребуется DOM test dependency, добавить только devDependency.

- [ ] Написать и запустить падающие сценарии: завершение сохраняет результат до анкеты; пропуск не создаёт good/normal/easy; отправка оценки показывает персонажа и советы; повторный вход не показывает анкету автоматически.
- [ ] Реализовать один переход анкета → персонаж/советы, кнопку «Исправить оценку» и немедленное закрытие. Не открывать AchievementReward автоматически поверх помощника; оставить отдельную кнопку наград.
- [ ] Подключить BASE_URL-safe пути артов и contain, alt-тексты; пользовательская картинка имеет приоритет. Комиксное облачко — HTML, текст не запечён в изображение. Учесть уменьшенную анимацию и узкий экран.
- [ ] Проверить изменение контекста, перезапуск страницы, отказ сохранения, пропуск анкеты, ноль подходов, история и повторное открытие наград. Не добавлять новый экран в процесс выполнения каждого подхода.
- [ ] pnpm test и pnpm build; commit интерфейса с четырьмя существующими изображениями и PROMPTS.md.
